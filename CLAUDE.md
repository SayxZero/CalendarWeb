# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## О проекте

**CalendarWeb** — сайт «Космос календаря»: планер в браузере для аккаунта
сервера синхронизации. Чистые ES-модули и CSS в `site/`, без сборки и
сторонних библиотек; тесты — `node --test`. Страницу отдаёт и связь с
сервером даёт бэкенд [CalendarWebServer](https://github.com/SayxZero/CalendarWebServer)
(`../CalendarWebServer`). Устройство — [DesDoc.md](DesDoc.md), что умеет —
[README.md](README.md).

Сабмодуль зонтичного репозитория
[CosmosCalendar](https://github.com/SayxZero/CosmosCalendar) (`..`): общий
`CLAUDE.md`, `DESDOC.md`, `ISSUES.md`. Планер — `../Calendar`: **логика сайта —
порт его логики**, и при правке модели, хранилища или обмена рядом надо
держать соответствующий файл планера (таблица в DesDoc.md, раздел 2).

## Проверка в браузере

Боевой сервер синхронизации (служба, 8765) не трогать. Для проверки:

1. тестовый сервер — `cmd //c "D:\\Prog\\Calendar\\CalendarServer\\run-server.bat" -p 8766 -d <папка в scratchpad> -noui` (в фоне);
2. бэкенд — `../CalendarWebServer/src/CalendarWebServer/bin/Debug/net10.0/CalendarWebServer.exe --host 127.0.0.1 -p 8780 -u 127.0.0.1:8766 -w D:/Prog/Calendar/CalendarWeb/site` (в фоне, после `dotnet build`);
3. встроенный браузер — `http://127.0.0.1:8780/`; тестовый аккаунт регистрируется
   на странице (его логин и пароль — в заметке scratchpad, не в чате).

Ширина телефона — `resize_window` с `preset: mobile`, потом обратно `desktop`.
Страница обновляется из файлов без сборки; перезагрузка — `navigate` с новым
`?r=N`, иначе браузер может взять модуль из кэша. Модули перерисовывают экран
на каждом обмене — ссылки `ref_N` из `find` быстро устаревают, надёжнее
координаты со свежего снимка.

**Дошло ли до планера.** Настоящий планер в песочнице, без его окна:

```bash
# вход тестового аккаунта (ключ - из POST /api/login ТЕСТОВОГО сервера)
cmake -S tools/planner-sandbox -B <scratchpad>/seed-build -G Ninja -DCMAKE_PREFIX_PATH=D:/Qt/6.5.3/mingw_64 && cmake --build <scratchpad>/seed-build
<scratchpad>/seed-build/seed-account.exe <папка песочницы> 127.0.0.1:8766 <логин> <ключ> <id>
../Calendar/release/CalendarPlanner.exe --data-dir <папка песочницы>      # в фоне: откроет аккаунт и синхронизируется
```

Что пришло — `accounts/<логин>.db` песочницы (`sqlite3`, только чтение: таблицы
`events`, `tasks`, `subtasks`, `completions`…); как выглядит — снимок окна через
PrintWindow по PID процесса песочницы (у владельца может быть запущен свой
планер). Песочницу потом остановить (`taskkill //PID … //F`) и удалить.

## Соглашения

- Строки интерфейса — по-русски, идентификаторы и комментарии — по-английски.
- **Формат записей — планера.** Новое поле записи появляется сначала в
  `JsonIo` планера; здесь его надо прочитать в `model/records.js`
  (`normalize`), иначе сайт его сохранит, но не покажет. Неизвестные поля
  `normalize` сохраняет — не ломать это.
- Правка, которая меняет записи, идёт через `Store` и зовёт `track()` на каждую
  затронутую запись (и каскады), как в `DataStore`; пришедшее с сервера — через
  `applyRemote()` без журнала.
- Цвета — только переменные палитры из `css/app.css` (`--accent`, `--text`…) и
  `--cal` для цвета календаря; своих цветов в коде нет.
- Обе раскладки — в каждом новом экране и окне: перелом 900 px (`isMobile()`).
  На телефоне период листается свайпом, окна — во весь экран.
- Ничего не загружается с других адресов (CSP бэкенда это запрещает) и нет
  `innerHTML` с данными пользователя — только `h()` и текстовые узлы.
- **В браузере не хранится ничего из аккаунта** и режима «нет связи» нет:
  бэкенд и сервер синхронизации — на одной машине, страница берёт аккаунт при
  каждом открытии и держит его в памяти. IndexedDB, Service Worker и прочие
  копии данных на стороне браузера не добавлять — это решение владельца.
- `append(null)` здесь безопасен (`dom.js` учит `append/prepend/replaceChildren`
  пропускать `null` и `false`) — так пишутся необязательные части экрана.
