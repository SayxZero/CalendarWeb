# Графика и ролики сайта

Всё, что показывает страница-презентация, делается отсюда одной командой:
картинки — из промптов, ролики — настоящими записями планера, сайта и телефона,
анимации — скриптами Blender. Результат ложится в `site/img` и `site/video` и
коммитится вместе с сайтом; всё рабочее (серверы, песочницы, сырые дубли) — в
`.work/`, он в `.gitignore`.

## Обновить после новой версии

Сначала соберите свежий планер (`Calendar/build-release.bat`) и сервер, поставьте
свежий APK на тестовый телефон и подключите его по USB. Потом из `CalendarWeb`:

```bash
node media/make.mjs                  # всё заново: около 12 минут
node media/make.mjs sheet            # листы кадров в .work/sheets: посмотреть глазами
```

Обычно столько не нужно. Что от чего зависит:

| Что изменилось | Команда |
|---|---|
| вид планера на ПК | `rec calendars alarm agent devices`, затем `blender alarm same-alarms devices`, `cut` |
| вид планера на телефоне | `rec taskcheck palette melody alarm devices`, затем `blender alarm same-alarms devices`, `cut` |
| вид сайта | `rec sharing taskcheck devices`, затем `blender devices`, `cut` |
| инструменты MCP или страница `agent/` | `rec agent`, `cut ai-agent` |
| только монтаж ролика (`videos.mjs`) | `cut <ролик>` — секунды, устройства не нужны |
| новая картинка | поправить `prompts/<имя>.txt`, `art --force <имя>`, `images` |
| фон роликов (`art/backdrop.png`) | `art --force backdrop`, `rec`, `blender`, `cut` |
| вид анимаций (`blender/*.py`) | `blender <имя>`, `cut <имя>` |

## Что где

| | |
|---|---|
| `make.mjs` | этапы: `art`, `images`, `rec`, `blender`, `cut`, `sheet`, `clean` |
| `scenes.mjs` | сцены записи: что и где нажимается |
| `videos.mjs` | монтаж и сжатие сырых дублей в `site/video` |
| `lib.mjs` | пути (переопределяются `MEDIA_*`), тестовые серверы, песочницы |
| `prompts/`, `art/` | запросы к ChatGPT и нарисованное им: `art/` — оригиналы, заново рисуется только по `--force` |
| `blender/` | сцены кодом, на экранах настоящие записи: `hero.py` (верх страницы), `devices.py` (три устройства), `alarm.py` (звонок на телефоне), `same-alarms.py` (ноутбук и телефон); модели — в `common.py` |
| `agent/` | панель чата для ролика про агента, без чужой символики; её вызовы и слова приходят от настоящего Codex, пока он работает |
| `tools/wdrive.cs` | нажатия и запись окон планера без настоящей мыши: посторонние окна в кадр не попадают |
| `tools/cdp.mjs` | нажатия и запись сайта в Edge без окна |

## Как устроена запись

Каждая сцена начинается с нуля: пустой тестовый сервер (порты 8771 и 8782, данные
в `.work/srv`), новый аккаунт `anna`, а записи в нём — собственные демо-данные
планера (`--demo`). Поэтому после обновления формат записей и даты всегда верные,
а дубль можно повторить. Боевой сервер не участвует. Телефон работает в песочнице
(`--data-dir`), в конце стоит обычный запуск планера. Палитра в записях —
«Небесная», её акцент совпадает с цветом сайта; звук будильников выключен.

**Ролик про агента** снимается на ПК, телефон ему не нужен. Планер в песочнице с
включённым режимом агентов и страница чата пишутся одновременно, а Codex (только с
этим сервером MCP, без настроек пользователя) работает с планером через настоящий
`CalendarPlannerMcp`. Его вызовы и слова читаются из `codex exec --json` и сразу
показываются на странице. Монтаж кладёт чат поверх записи планера и вырезает из обеих
одни и те же паузы, пока агент думает. Сцена падает, если правок меньше четырёх или
на тестовый сервер ничего не дошло. Ответ агента каждый раз новый: после записи
прочитайте журнал и `sheet ai-agent`, неудачный дубль снимается заново. В понедельник
демо-задача «Дочитать книгу» лежит ещё на этой неделе, и в кадре не видно, как она
закрывается: такой день для съёмки лучше не брать.

## Если съехали нажатия

На сайте сцены находят кнопки по тексту и селектору и переживают почти любую
правку. На ПК и телефоне нажатия — в пикселях:

- ПК: окно стоит в `73,10`, размер `1454×845`, масштаб 125 %. Точки — в объекте
  `P` в начале `scenes.mjs`, у сцены агента своё окно и свои точки (`AGENT_WINDOW`,
  `AGENT_P`). Снимок: `.work/wdrive.exe grab <окно> файл.png`.
- Телефон: 720×1600, нажатия прямо в сценах (`phone.tap`, `phone.swipe`). Каждое
  записывается и рисуется поверх кадра:
  `applyTouches()` в `lib.mjs`, сырая запись лежит рядом как `<сцена>.raw.mp4`. Снимок: `phone.shot`
  или `adb exec-out screencap -p`.

Открытый Blender со сценой `devices.py` держит файлы записей: перед `rec` закройте
её, иначе запись остановится с сообщением об этом.

Сцену проще чинить по одной: `node media/make.mjs rec calendars`, затем
`cut calendars` и `sheet calendars`.

## Что нужно на машине

Node.js, .NET SDK, ffmpeg, Blender 3.5+, Qt с MinGW, Edge, `adb`; пути — в начале
`lib.mjs`. Ещё нужны:

- **scrcpy** — запись экрана телефона (на этом Realme `screenrecord` закрыт для adb).
  Архив `scrcpy-win64-v5.0.1.zip` с [github.com/Genymobile/scrcpy](https://github.com/Genymobile/scrcpy/releases)
  распаковать в `.work/scrcpy/`, SHA-256
  `b12a2c4ee8be317422451fc7dcf8ee20a71b5ea7ef9ad73ddd825a25316227a5`.
- **Codex CLI** с действующей подпиской ChatGPT — для новых картинок и сцены агента
  (`npm i -g @openai/codex`). Без подписки рисование отвечает `403 Forbidden`.
  Модель — `MEDIA_CODEX_MODEL`, по умолчанию `gpt-6-luna`.
